## 目标与范围
- 新增一个仅管理员可访问的后台管理区（/admin），用于管理用户与账户。
- 复用 Better Auth 的 Admin 插件实现用户管理能力（用户列表、设置角色、封禁/解封、重置密码、会话查看/吊销、删除用户）。
- 额外补齐“账户（Account）”管理：查看账号绑定信息（providerId/accountId/所属用户）与解绑（删除 Account 记录）。

## 现状调研结论
- 当前项目只有一个 [app.vue](file:///home/ubuntu/projects/sso-auth-nuxt/app/app.vue) 演示登录/注册；没有 pages 路由体系、没有 /admin 页面、也没有 Nuxt 路由鉴权中间件。
- 服务端 Better Auth 实例在 [auth.ts](file:///home/ubuntu/projects/sso-auth-nuxt/server/lib/auth.ts)，并通过 [server/api/auth/[...].ts](file:///home/ubuntu/projects/sso-auth-nuxt/server/api/auth/[...].ts) 暴露 /api/auth/**。
- Prisma 模型目前只有 User/Session/Account/Verification（无角色/封禁字段）：[schema.prisma](file:///home/ubuntu/projects/sso-auth-nuxt/prisma/schema.prisma)

## 方案概述（推荐实现路径）
### 1) 接入 Better Auth Admin 插件（用户管理）
- 服务端：在 [auth.ts](file:///home/ubuntu/projects/sso-auth-nuxt/server/lib/auth.ts) 的 plugins 中加入 `admin()`。
- 客户端：在 [auth-client.ts](file:///home/ubuntu/projects/sso-auth-nuxt/app/utils/auth-client.ts) 的 `createAuthClient` 增加 `plugins: [adminClient()]`，让前端可以调用 `authClient.admin.*`。
- 管理员判定与自举：
  - 默认采用 Admin 插件的 admin 角色体系（role 字段）。
  - 额外支持通过环境变量 `ADMIN_USER_IDS`（逗号分隔）配置初始管理员，避免首次没有管理员无法进入后台。

### 2) 数据库与 Prisma Schema 变更
- 按 Admin 插件要求扩展表结构（在 Prisma schema 中体现）：
  - User：新增 `role`、`banned`、`banReason?`、`banExpires?`
  - Session：新增 `impersonatedBy?`
- 生成并执行 Prisma migration，确保与 better-auth/prismaAdapter 匹配。

### 3) 建立 Nuxt 页面路由结构（从单一 app.vue 迁移）
- 将当前登录/注册 Demo 从 `app/app.vue` 迁移到 `app/pages/index.vue`。
- 将 `app/app.vue` 改为根壳组件（包含 `<NuxtPage />`），启用 pages 路由。

### 4) 新增后台页面（前端）
- 路由与页面：
  - `/admin`：后台首页/导航
  - `/admin/users`：用户列表（搜索、分页）
  - `/admin/users/[id]`：用户详情（改名/改角色/封禁解封/重置密码/会话列表与吊销/删除）
  - `/admin/accounts`：账户列表（Account 记录）与解绑
- 访问控制（前端体验层）：
  - 新增 `app/middleware/admin.ts`：访问 /admin* 时，先取 session；无 session 则跳转 `/`；有 session 再尝试调用一次 `authClient.admin.hasPermission`（或直接试探 `listUsers`）来确认管理员权限，不通过则显示“无权限”。
  - 即便前端绕过，后端接口也会做强制校验（见下一节）。

### 5) 新增账户管理 API（后端）
- 由于 Admin 插件主要覆盖“用户/会话”管理，账户表（Account）管理补齐为自定义 Nitro API：
  - `GET /api/admin/accounts`：分页/筛选返回账户绑定列表（providerId/accountId/userId + 用户 email/name）
  - `DELETE /api/admin/accounts/:id`：解绑（删除 account 记录）
- 接口统一使用服务端管理员校验：
  - 通过 `auth.api.getSession({ headers })` 获取当前会话；再用 `auth.api.userHasPermission({ body: { userId, permissions: { user: ["list"] } }, headers })` 验证为管理员。

## 安全与权限要点
- 后台与 /api/admin/** 必须强制要求管理员会话（服务端校验为准）。
- 默认不返回敏感字段（如 accessToken/refreshToken/idToken/password），账户列表仅用于“绑定关系可视化 + 解绑”。
- 删除用户/解绑账户属于高风险操作，UI 上增加二次确认与明显的警示文案。

## 验证方式
- 本地运行后验证：
  - 普通用户访问 `/admin` 被拒绝。
  - 管理员可进入后台并完成：用户列表/封禁解封/设置角色/重置密码/会话吊销。
  - 账户列表不暴露 token/password 字段；解绑后关联用户的 provider 登录会受影响（预期行为）。
- 对关键 API 做最小化接口测试（至少覆盖：未登录、非管理员、管理员三种情况）。
